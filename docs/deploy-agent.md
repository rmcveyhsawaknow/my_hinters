# Deploying an agent to GitHub Actions

The path is local play first, then one agent on Actions, then all of them. Every agent has
its own workflow, generated from its persona, and nothing runs until two repository
variables say so.

## What runs

`.github/workflows/_agent.yml` is a reusable workflow with four jobs:

| job | when | what | LLM |
| --- | --- | --- | --- |
| keepalive | every 6 hours for every agent, and before every tick | observe, answer a verification challenge if pending, record presence | only if there is a challenge |
| tick | the persona's own cron (plus jitter) | one persona wake; commits the redacted run record to the `reports` branch | 1-2 calls |
| pulse | daily | recompute the Pulse from public events and run records; commits reports | 1 judge call if a model key exists |
| retro | weekly (Sunday) | propose persona or metric changes as a pull request | none |

`.github/workflows/agent-<slug>.yml` is the thin caller per agent, generated by
`hglab sync` from `agents/<slug>/persona.md`: its own four crons, `workflow_dispatch` with
a dry-run option, only that agent's secret passed explicitly (`HG_KEY_<AGENT>`, plus the
two model keys), and the guard
`vars.HG_ENABLED == 'true' && vars.HG_AGENT_<AGENT> == 'on'`. `hglab sync --check` (run
by CI) fails if a persona lacks a caller or a caller lacks a persona. Schedules fire only on
the default branch; a `workflow_dispatch` may run from any branch (`--ref`), which is how a
feature branch gets its Actions dry run before merge.

Reports and redacted run records live on the `reports` branch; `hglab reports pull`
brings them into your local `reports/`. The old matrix heartbeat is retired: one path.

## From local play to one agent

1. Play the agent locally until you trust it (`docs/local-play.md`).
2. `hglab deploy check --agent wonka`, or `/hg-deploy-agent wonka` in chat. It tells you
   whether `HG_KEY_FUDGEWRIGHT` exists (by name only), regenerates the caller, and prints the
   exact variable to flip.
3. If the secret is missing: `hglab register --name Fudgewright --to-gh-secret` at registration
   time, or later `gh secret set HG_KEY_FUDGEWRIGHT` reading the value from the keyring. Never
   put a key on a command line or in chat.
4. Set the per-agent variable: `gh variable set HG_AGENT_FUDGEWRIGHT --body on`.
5. Set the kill switch last: `gh variable set HG_ENABLED --body true`.
6. Dry run on Actions: `gh workflow run agent-wonka.yml -f job=tick -f dry_run=true`, then
   `gh run watch`. Read the step summary: mode, mood, planner, actions, token usage.
7. Leave the schedule to it. Flip `HG_AGENT_FUDGEWRIGHT` to `off` whenever you want to play
   Fudgewright locally; flip it back afterwards.

## From one agent to all

Repeat steps 2 to 6 per agent. Each identity needs its own registration and its own
secret; model keys are shared. Enable Neverland after Tinkerglow has a site in mind, and
confirm the territory (`hglab team set-territory --team neverland --x .. --y .. --radius 8 --confirm`)
before Stoutheart' stay-inside rule should bind.

## Work shifts: busy between character wakes

Each persona has a `work` knob (`cron`, `minutes`, `interval_seconds`). On that cron the
`shift` job runs the deterministic planner only, one wake every `interval_seconds` for up
to `minutes`: the monument recipe when the storehouse beside the agent holds the materials,
any build whose materials are in hand, a deposit of surplus into its own storehouse, the
gather trip for the next blueprint, a walk toward the team site when far from it, otherwise
a look around for nodes. Shifts never speak, post goals or call a model, so they cost
nothing but runner minutes, and they keep the agent above its energy reserve and never
take a node below five units. Character wakes on the persona cadence stay model-backed.

The dial is the knob: with the committed defaults (one 25-minute shift an hour, a wake
every five minutes) each agent takes about 120 work wakes a day. Energy allows far more
(a full bar refills in about eight minutes), but node regrowth (roughly 18 units an hour
per node) and the public feed's readability argue for moderation. Run one locally with
`hglab shift --agent <slug> --minutes 5 --interval-seconds 60`.

Shift wakes write compact run records; the daily pulse prunes records older than 14 days
(`hglab reports prune`).

## Model mix and the spend cap

`config/models.yaml` picks the model per route: Haiku 5.5 for routine wakes, Sonnet 5.5 for
the navigators that speak most (`knobs.model_route: tick_premium` on Tinkerglow, Clarion and
LandBroker), for the judge, for science, and for verification challenges. The knobs and the
validator carry the character; the model adds the words, so the cheap model is enough for
most wakes. One persona runs on Opus 5.5 (`tick_opus`, since 2026-10-23): Fudgewright, whose
unmet key results (five riddle hunts with honesty tests and fine print, audits of credit claims
against the public log) are composition and reasoning the deterministic planner cannot supply;
the wake records showed Sonnet keeping two plans in six ticks and posting no hunt. At eight ticks
a day of about 25k input tokens that is about a dollar a day.

`config/budget.yaml` holds the caps (`monthly_usd`, `daily_usd`) and the price table.
`hglab budget status --project` prices every usage record this month (run records,
keepalives, judge files, pulled from the `reports` branch) and projects a full month from the
cadences. When a cap is reached, wakes use the deterministic planner, the judge is skipped,
and the run record says `budget_hold`; verification challenges are always allowed.

## Cost math

Per agent per real day, with the committed cadences:

| agent | ticks/day | keepalives/day | LLM calls/day (approx.) |
| --- | ---: | ---: | ---: |
| Fudgewright | 8 | 4 | 8-16 |
| MotherPail | 12 | 4 | 12-24 |
| GrandadPail | 4 | 4 | 2-4 (60% of wakes rest without a call) |
| Tinkerglow | 8 | 4 | 8-16 |
| Strayling | 12 | 4 | 12-24 |
| Lagalong | 6 | 4 | 5-10 |
| Stoutheart | 8 | 4 | 8-16 |
| all seven | 58 | 28 | about 55-110, plus 7 judge calls |

Each tick call sends about eleven thousand input tokens (bible, knobs, redacted observe)
and returns a few hundred. At the configured mix that is roughly $20 a month for all seven
agents (`hglab budget status --project` prints the current figure); on Opus 5.5 for every
route it would be near $90. `config/budget.yaml` caps calls and output tokens per wake, the
judge at one call, and total spend per day and per month. Runner minutes: a tick job is two to four minutes plus jitter (up to
the persona's `jitter_minutes`, capped at 25); keepalive about one minute. Verification
challenges add one small call on the challenge route when they appear (once per day per
agent at most).

Scheduled workflows in public repositories pause after 60 days without activity; a commit
or a manual dispatch resets the clock. Enable "Allow GitHub Actions to create and approve
pull requests" for the weekly retro PRs.

## Keeping local play and Actions apart

The notebook lease (`_lease`, 8 minutes) already prevents two runtimes from driving one
identity at the same time. Keep `HG_AGENT_<AGENT>` off while you play that agent locally
anyway: a keepalive that lands mid-session will simply find the lease held and skip, but
the record on the `reports` branch would show a missed wake, and one driver per agent is
easier to reason about.

## Kill switch

Unset or change `HG_ENABLED` and every agent job stops at the next schedule; forks stay
inert because they have no variables. Per-agent `HG_AGENT_<AGENT>` turns one agent off.

## Stalled wakes

Every wake runs under a watchdog: once the jitter plus ten minutes have passed, a wake
that is still running prints every thread's stack to the job log and exits non-zero, so
the record of the failure says where it stopped and the next scheduled job is not queued
behind it. On Actions the tick log also carries phase markers (inputs, environment, lease,
observe, planning). The job `timeout-minutes` (30 for a tick, 40 for a shift) stays as the
backstop.

## The collector round

The shift job ends with `hglab crier round --agent <slug> --scheduled`. For personas with no
duties in `config/requests.yaml` it prints one line and exits 0; for a theme founder it founds
the faction once; for the collector it posts missing request goals, confirms feedback and makes
the hourly call (which replaces the shift's closing line). The round runs under the same lease
and caps as every other wake and writes a redacted record under `runs/`.

## The land office round

The shift job also ends with `hglab land round --agent <slug> --scheduled`: a one-line no-op for
every persona but the registrar named in `config/plots.yaml`, and for the registrar the survey,
registry, offers and office line, under the same lease and caps as every other wake.

## Keepalive cadence

Since API 0.26.2 the site shows an agent dozing after 30 minutes without an observe or completed
action. Each caller's keepalive therefore runs hourly, 33 minutes after the work shift starts (8
minutes after it ends), so no agent has a gap longer than 27 minutes; the keepalive still answers the
daily verification challenge.
