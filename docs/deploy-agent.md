# Deploying an agent to GitHub Actions

The path is local play first, then one agent on Actions, then all of them. Every agent has
its own workflow, generated from its persona, and nothing runs until two repository
variables say so.

## What runs

`.github/workflows/_agent.yml` is a reusable workflow with four jobs:

| job | when | what | LLM |
| --- | --- | --- | --- |
| keepalive | every 6 hours for every agent, and before every tick | observe, answer a verification challenge if pending, record presence | only if there is a challenge |
| tick | the persona's own cron (plus jitter) | one persona wake; commits the redacted run record to the `reports` branch | 1-2 calls |
| pulse | daily | recompute the Pulse from public events and run records; commits reports | 1 judge call if a model key exists |
| retro | weekly (Sunday) | propose persona or metric changes as a pull request | none |

`.github/workflows/agent-<slug>.yml` is the thin caller per agent, generated by
`hglab sync` from `agents/<slug>/persona.md`: its own four crons, `workflow_dispatch` with
a dry-run option, only that agent's secret passed explicitly (`HG_KEY_<AGENT>`, plus the
two model keys), and the guard
`vars.HG_ENABLED == 'true' && vars.HG_AGENT_<AGENT> == 'on'`. `hglab sync --check` (run
by CI) fails if a persona lacks a caller or a caller lacks a persona. Schedules fire only on
the default branch; a `workflow_dispatch` may run from any branch (`--ref`), which is how a
feature branch gets its Actions dry run before merge.

Reports and redacted run records live on the `reports` branch; `hglab reports pull`
brings them into your local `reports/`. The old matrix heartbeat is retired: one path.

## From local play to one agent

1. Play the agent locally until you trust it (`docs/local-play.md`).
2. `hglab deploy check --agent wonka`, or `/hg-deploy-agent wonka` in chat. It tells you
   whether `HG_KEY_FUDGEWRIGHT` exists (by name only), regenerates the caller, and prints the
   exact variable to flip.
3. If the secret is missing: `hglab register --name Fudgewright --to-gh-secret` at registration
   time, or later `gh secret set HG_KEY_FUDGEWRIGHT` reading the value from the keyring. Never
   put a key on a command line or in chat.
4. Set the per-agent variable: `gh variable set HG_AGENT_FUDGEWRIGHT --body on`.
5. Set the kill switch last: `gh variable set HG_ENABLED --body true`.
6. Dry run on Actions: `gh workflow run agent-wonka.yml -f job=tick -f dry_run=true`, then
   `gh run watch`. Read the step summary: mode, mood, planner, actions, token usage.
7. Leave the schedule to it. Flip `HG_AGENT_FUDGEWRIGHT` to `off` whenever you want to play
   Fudgewright locally; flip it back afterwards.

## From one agent to all

Repeat steps 2 to 6 per agent. Each identity needs its own registration and its own
secret; model keys are shared. Enable Neverland after Tinkerglow has a site in mind, and
confirm the territory (`hglab team set-territory --team neverland --x .. --y .. --radius 8 --confirm`)
before Stoutheart' stay-inside rule should bind.

## Cost math

Per agent per real day, with the committed cadences:

| agent | ticks/day | keepalives/day | LLM calls/day (approx.) |
| --- | ---: | ---: | ---: |
| Fudgewright | 8 | 4 | 8-16 |
| MotherPail | 12 | 4 | 12-24 |
| GrandadPail | 4 | 4 | 2-4 (60% of wakes rest without a call) |
| Tinkerglow | 8 | 4 | 8-16 |
| Strayling | 12 | 4 | 12-24 |
| Lagalong | 6 | 4 | 5-10 |
| Stoutheart | 8 | 4 | 8-16 |
| all seven | 58 | 28 | about 55-110, plus 7 judge calls |

Each tick call sends a few thousand input tokens (bible, knobs, redacted observe) and
returns a few hundred; `config/budget.yaml` caps calls and output tokens per wake and the
judge at one call. Runner minutes: a tick job is two to four minutes plus jitter (up to
the persona's `jitter_minutes`, capped at 25); keepalive about one minute. Verification
challenges add one small call on the challenge route when they appear (once per day per
agent at most).

Scheduled workflows in public repositories pause after 60 days without activity; a commit
or a manual dispatch resets the clock. Enable "Allow GitHub Actions to create and approve
pull requests" for the weekly retro PRs.

## Keeping local play and Actions apart

The notebook lease (`_lease`, 8 minutes) already prevents two runtimes from driving one
identity at the same time. Keep `HG_AGENT_<AGENT>` off while you play that agent locally
anyway: a keepalive that lands mid-session will simply find the lease held and skip, but
the record on the `reports` branch would show a missed wake, and one driver per agent is
easier to reason about.

## Kill switch

Unset or change `HG_ENABLED` and every agent job stops at the next schedule; forks stay
inert because they have no variables. Per-agent `HG_AGENT_<AGENT>` turns one agent off.
